PROBLEM STATEMENT:
We have a Hybris system with:
- 735,349+ products
- 1,196,160+ media files
- Multiple product-to-media reference types (direct attributes, collections, containers)
- Significant orphaned/unused media (398,698+ files)

The media references are stored in the Product table across multiple attributes:
  * Direct single-value references: thumbnail, picture, logo, data_sheet, others, videos, mobileImages
  * Collection references (comma-separated PKs): normal, thumbnails, detail
  * Container references: galleryImages (which link to MediaContainers containing multiple media)

Problem: When media is deleted from the Media table, product references remain as broken links. 
We need accurate statistics based on what actually exists in the Media table, not what products claim to reference.

REQUIREMENTS:

1. STATISTICS SCRIPT (prodMediaStatsScript)
   Purpose: Generate media audit report with before/after deletion comparison
   
   Output Format Needed:
   - Total Categories count
   - Category media attribute counts (thumbnail, picture, normal, thumbnails, detail, logo, data_sheet, others)
   - Total Products count
   - Product media attribute counts (thumbnail, picture, normal, thumbnails, detail, logo, data_sheet, others, videos, mobileImages)
   - Gallery container count
   - Gallery media count
   - ALL DISTINCT PRODUCT MEDIAS (consolidation of all media from all sources)
   - TOTAL MEDIA COUNT (all media in Media table)
   - UNUSED MEDIA COUNT (Total - Used)
   - DURATION (execution time)
   
   Counting Logic:
   - For each attribute, count media PKs that BOTH:
     a) Are referenced by products in that attribute
     b) Actually exist in the Media table
   - Handle three types of references:
     * Direct: single PK stored as attribute value
     * Collection: comma-separated PKs stored as attribute value (split on comma)
     * Container: PKs pointing to MediaContainers which contain media via {med.mediaContainer} join
   - Remove nulls, empty strings, whitespace-only values, and lines starting with '#'
   - Use batching (10,000 items per query batch) for large result sets
   - Consolidate all media PKs into single distinct set as SOURCE OF TRUTH for "used" count

   - Root and destination directories per protocol
   - File thresholds and pagination settings
   
   Processing Logic:
   - Pagination: Process products in 40,000-item batches (pages)

       - getProductThumbnail() - direct {thumbnail} attribute
       - getProductPicture() - direct {picture} attribute
       - getProductMediaPkFromMediaCollection() - collection attributes
       - getProductMediaPkFromMediaContainer() - gallery containers
     * Consolidate into single distinct set
     * Query Media table for location/details
     * Write to files (split at 40,000 rows)
   - Output format: media PK;location pairs
   - Also export product codes for cross-reference
   - Log everything with timestamps

3. SCRIPT EXECUTION REQUIREMENTS
   - Format: Hybris Groovy Cron Job / Script Job (return CronJobResult.SUCCESS/ERROR)
